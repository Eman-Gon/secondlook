SecondLook tested a Python application while upgrading the PyPI package Pydantic from version 1.10.18 to version 2.8.2. The comparison was checked at 2026-09-22T02:15:49.211286+00:00. Its recorded outcome is confirmed_break. The verified run identifier is 20260922T021505Z-c34945a8.

The affected application is demo/upgrade/app.py. Its Customer model declares the field Customer.nickname on line 10 as nickname: Optional[str], without an explicit default. The import_row function constructs Customer from a supplied row and returns the customer's name and nickname. These relationships connect the Pydantic dependency, the Customer model, the nickname field, the import_row function, and the behavior of importing a row with an omitted nickname.

The application expects import_row({"name": "Ada"}) to return {"name": "Ada", "nickname": null}. In this document, JSON null corresponds to Python None. Pydantic 1.10.18 accepts the missing nickname and gives it the value None. Pydantic 2.8.2 rejects the same input because an Optional annotation allows None as a value but does not itself supply a default. The new-version probe produced a ValidationError for Customer.nickname with the message Field required.

The six measured executions establish the following comparison. On the original application, the two existing tests for an explicit nickname and explicit None both passed under Pydantic 1.10.18, and both passed under Pydantic 2.8.2. The newly generated test_missing_nickname probe passed under 1.10.18 with exit code 0 and failed under 2.8.2 with exit code 1. After applying the proposed explicit-default fix, the same missing-nickname probe passed under both 1.10.18 and 2.8.2 with exit code 0. Each run printed exactly one installed-dependency version marker matching its intended version. The fixed executions verified the new probe; they did not rerun the two existing tests.

The verified fix changes Customer.nickname from nickname: Optional[str] to nickname: Optional[str] = None. This makes omission explicit and preserves the expected import_row result for the measured input across both dependency versions. The patch was applied only to a separate test copy for this comparison.

The official upstream explanation is Pydantic v2.8 Migration: Required, optional, and nullable fields.
Source URL: https://pydantic.dev/docs/validation/2.8/get-started/migration/
